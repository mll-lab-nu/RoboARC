# roboarc-ikea (the IKEA MuJoCo images)

`ghcr.io/embodied-first-exam/roboarc-ikea:<images/ikea-mujoco/VERSION>`: MuJoCo 3.14.0 (the PyPI wheel with the EPA
horizon-overflow fix byte-patched in; CPU, float64; numpy 2.5.4, Python 3.12) and the twelve IKEA furniture scenes of
the IKEA MuJoCo tasks (`tasks/roboarc-ikea-<scene>-i00-{privileged,standard}`, generated by
`scripts/ikea_mujoco/mk_tasks.py` and `mk_standard_tasks.py`; benchmark page: `docs/benchmarks/ikea_mujoco.md` at the
repository root). Every scene is a task in both modes.

Each scene is self-contained in `/opt/ikea/scenes/<scene>/`: `scene.py` (`load()` returns the scene: `S.model`,
`S.data`, `S.step(n)` = n physics steps plus the scene's mechanism, `S.success()`), `scene.xml` with the two arms, the
scene's mechanism and success modules, `task.json`, `layout.json`, `assets/` (meshes). The image holds no task code:
the tooling (`rcb_ikea.py`) and the graders are copied by each task, and no robot demo or direct-force reference is in
it. The scenes were authored by Xiaoyu and Zhen Wu's team.

`sim/` is the standard tasks' sidecar image, `ghcr.io/embodied-first-exam/roboarc-ikea-sim:<images/ikea-mujoco/sim/VERSION>`:
this image unchanged as the physics process, plus Nyx (RoboARC's renderer) in its own venv `/opt/nyx`
(`sim/nyx-requirements.txt`: RoboARC's exact versions and wheel hashes), the Vulkan loader and NVIDIA ICD / EGL vendor
files, imageio + ffmpeg, Pillow and PyOpenGL.

## Build source

The scene code is in git, `scenes/<scene>/` here. The meshes (`scenes/<scene>/assets/`, 2,078 files, about 40 MB per
scene) are not: they are on a private Hugging Face dataset (layout `<scene>/assets/<file>`), pinned by its revision and
by the sha256 of every file in `scripts/ikea_mujoco/assets.json` (`repo`, `revision`, and per scene `files`). Every
task's `tests/runtime_binding.json` repeats its scene's pins, which the grader checks in the verifier image
(`instance_exact`) together with the initial-state hash (`instance_ok`).

What is staged per scene: `scene.py`, `scene.xml`, `task.json`, `layout.json`, `sw_cutover.json` (where present), the
scene's own Python modules (not `_*.py` scripts) and `assets/`; then `assets.json` (its `note` and `tasks`, the pins the
image carries at `/opt/ikea/assets.json`) and `bytepatch_libmujoco.py`, the EPA patch script, from RoboARC's one copy
in `source/images/roboarc/mujoco-3.14.0-epa/` (`docs/simulator/MUJOCO_EPA_PATCH.md` describes the patch). `stage_context.py` refuses any
file whose sha256 differs from the pins and any scene text that points at upstream material (PROTOCOL Appendix H.2);
the scenes' upstream provenance is kept out of the image, in `scripts/ikea_mujoco/provenance.json`.

## Build (paths from `ikea/`)

```bash
images/ikea-mujoco/build.sh                    # meshes at the pinned revision (needs read access: `hf auth login` or HF_TOKEN)
images/ikea-mujoco/build.sh --assets <dir>     # or a local copy of the meshes, <dir>/<scene>/assets/
```

`build.sh` stages the scene code with the meshes into `images/ikea-mujoco/context/` (`stage_context.py`, every file
checked against `scripts/ikea_mujoco/assets.json`), builds `ghcr.io/embodied-first-exam/roboarc-ikea:<VERSION>` from it,
then `ghcr.io/embodied-first-exam/roboarc-ikea-sim:<sim/VERSION>` FROM it, and checks that the base image is the one
every task is bound to (`scripts/ikea_mujoco/bindings.json`).

The build needs network access to docker.io, pypi.org (and download.pytorch.org, dl.polyhaven.org for `sim/`); running
needs none. Host: Linux x86_64, Docker; the base image needs no GPU, the sidecar an NVIDIA GPU with Vulkan and EGL.

A rebuild from the same context on a host that holds the build's layer cache gives the same image ids (above). A build
from scratch installs the same wheels (the patch script asserts the wheel's and the patched `.so`'s sha256) and the same
scene files, but its layers, and so its id, differ. The sidecar image's apt layer follows the Debian archive of its
build day, so its id differs per build host. After a scene changes: `stage_context.py <tree> --pin`, rebuild, bump
`VERSION`, refresh `scripts/ikea_mujoco/bindings.json` (`python /opt/tools/rcb_ikea.py info --task <scene>` in the image,
per scene), upload the meshes as a new dataset revision and pin it, and re-render the tasks. A changed scene is a new
task (PROTOCOL §2.8).

## Registry

The tasks name the tags; `scripts/ikea_mujoco/bindings.json` holds the base image's id, which every privileged task's
`tests/runtime_binding.json` and every standard task's `environment/sim/runtime_binding.json` repeat. The build context's
source of record is the dataset revision in `scripts/ikea_mujoco/assets.json`. Before RoboARC 1.0.0 the same two images
(same ids) were published as `eai-ikea-mujoco:0.3.2` and `eai-ikea-mujoco-sim:0.4.2`; the IKEA task texts and
evidence records of earlier runs keep those names.
